# Owned HTTP controlled-reader contract

This service is a loopback-only simulation, not a vendor API. Implement `ControlledHttpReader(client)` and `create_adapter(config_path)` in `source/http_controlled_reader.py`. Use the trusted SDK `HttpControlClient` and fixed `HttpControlOperation` definitions. No endpoint discovery, credentials in source, production address, automatic retry or physical safety claim. The factory requires separate private `airalogy.http-control-config.v1`, loopback address and exactly the operation names below. Independent tests supply a fake client with arbitrary result values, not the adapter's own simulator.

All responses are JSON objects with `simulation_only: true`. Operations are fixed: `identity` GET `/v1/identity`; `state` GET `/v1/state`; `configure` PUT `/v1/parameters` with exactly `operation_id`, `sample_count`; `start` POST `/v1/start` with exactly `operation_id` (202 response); `result` GET `/v1/result` with exact `operation_id` query; `stop` POST `/v1/stop` with exactly `operation_id`. Other success statuses are 200. Writes return exactly `{accepted: true, operation_id, simulation_only: true}`. Acceptance is not completion. Errors/lost responses must propagate without resending the write.

`identity` contains exactly `target` and `simulation_only`. Target fields are bounded nonempty strings: `identity_reference`, `firmware`, `application`, `application_version`, `driver_version`, `os_version`. State contains exactly `state`, `operation_id`, `sample_count`, `ready`, `owner`, `operator_confirmed`, `simulation_only`. Booleans must be actual booleans. Owner is `gateway` or `human`. Idle has null operation/count; configured/running/complete/stopped have a canonical UUID and integer count 1–96. The service begins idle, configures once, and completes after two running observations; a fresh service represents one acquisition. No reset/restart operation exists.

Only `reader.measure@1.0.0` is supported, with integer `sample_count` 1–96 (not boolean). Use the exact SDK Instrument Job `job.job_id` UUID as operation_id. Before configuring, require idle, ready, Gateway ownership and operator confirmation. Configure once, independently read back configured state, exact UUID/count and conditions, then start once. Confirm/preflight read fresh state; `reader.ready` requires idle/ready/Gateway ownership; operator presence is the observed flag, emergency-stop availability is false because this is simulation.

Poll for at most five seconds; each network operation also has a bounded timeout. Every observation must preserve UUID/count and local conditions. Completion requires exact result fields `operation_id`, `sample_count`, finite numeric `value` (not boolean), `unit: synthetic_unit`, `simulation_only: true`. Return the server's value unchanged, never compute a replacement. After result receipt, read fresh complete state and recheck UUID/count/conditions. Unknown state, timeout, takeover, cancellation or mismatch is failure, never successful completion.

Errors are reconciled by the Gateway. Safe-stop reads the state without reusing the cancelled execution event. Idle with no operation needs no write; a different UUID must never be stopped. For this UUID, request stop only if not already stopped, then independently read back stopped with the same UUID. Lost/invalid stop responses remain uncertain. A later recovery may inspect the state and acknowledge already stopped without another stop. This simulation contract does not establish physical stopping semantics; a vendor implementation needs separate documentation, approval and real qualification.
