# 导入与导出

导入与导出会让研究数据跨越系统边界。开始前应确认目标位置、操作授权、schema 和数据保留要求。

## 从 CSV 导入 Record

启用批量上传后，CSV 每一行会在所选 Protocol 下创建一条新 Record，不会覆盖已有 Record。

1. 打开目标 Protocol 的 Records 页面。
2. 选择“批量上传”，点击“下载 CSV 模板”。模板根据当前 Protocol 版本生成，只有标准表头，不包含虚构示例数据。
3. 展开字段说明，按字段类型、必填项、范围和枚举整理数据，保存为 UTF-8 CSV（支持 BOM）。
4. 选择文件并点击“预检文件”。修正提示的字段和行后重新预检；预检不会创建 Record。
5. 核对目标 Protocol、版本和创建数量，勾选确认后点击“确认导入”。导入后抽查有代表性的 Record。

模板使用 `var.sample_id` 等明确路径。**字段 ID 必须与 Protocol 一致，区分大小写，不使用中文显示标题代替，不猜测表头或自动映射旧表格。** 列顺序可以变化，可选列可以省略；未知列（即使整列为空）、重复列和指向同一字段的重复路径都会拒绝。直接变量名 `sample_id` 与 `data.var.sample_id` 保留为既有接口的合法写法。

受支持的路径还可指向 quiz、步骤/检查项状态与备注、metadata，以及可选的 `record_id`。单元格按当前 Protocol 字段类型转换和校验；已声明的默认值按 Protocol 定义处理。数组、对象等复杂字段应遵循其 JSON 结构，文件引用还需具备当前访问权限。

```csv
var.sample_id,var.amount
S1,12
S2,18
```

这个例子仅适用于定义了 `sample_id` 和 `amount` 的 Protocol。不要把说明行或示例值当作真实研究数据导入。

- 数字 `0` 是有效观测值，不等于空白。不要用 `0`、`false` 或推测值补齐缺失观测。
- `#REF!` 等表格错误需要回到原始数据核实；平台不会代为计算、删列或修正量表结果。
- 错误按字段分组，CSV 行号包含表头；含换行单元格时显示记录起始的文件行号。任何一行不通过，该批次都不会部分写入。
- CSV/TSV 支持最多 10,000 条记录、512 列；普通导入文件最多 20 MiB。超限请分批整理。
- 预检确认有效期为 20 分钟，并绑定文件、Protocol 版本和用户。文件或 Protocol 变化后需要重新预检；确认时仍会检查当前权限、数据和资源条件。
- `.aira` 归档继续使用独立的归档导入校验流程，不提供 CSV 预检。既有 API 调用方仍可直接提交导入，但不能绕过数据校验与权限检查。

## 下载 Protocol

选择“下载 → Airalogy 归档（.aira，推荐）”，获取包含 Protocol、资源文件和经过校验的标准清单的归档；需要普通解压编辑时选择“源文件包（.zip）”。两种格式均对应请求的 Protocol 版本，不导出数据库 Records，也不授予接收者平台权限。`.aira` 带有文件哈希校验，不是将 ZIP 改名。导出排除环境密钥、解释器缓存和运行时生成文件；源文件包不符合归档标准时会阻止 `.aira` 导出，可使用 ZIP 检查修复。原有 ZIP 下载接口仍兼容既有集成。

## 导出 Record

启用导出功能后，获授权的 Lab 或 Project 角色可以申请限定范围的 Record 导出。可用格式可能包括 `.aira`、JSONL、单 schema CSV、附件和可选修订历史。导出代表所选范围在固定时间点的快照，不会为接收者增加新的 Platform 权限。

导出文件可能包含未公开或敏感研究数据。只能存放在获准位置，通过获准渠道传输，并按规定清理临时副本。下载链接可能过期；需要时应从 Platform 重新生成，不要长期转发旧链接。

## 核对每次迁移

- 记录来源范围、Protocol 版本、筛选条件、导出时间和申请人。
- 迁移前后核对数量与关键 ID。
- 单独检查 CSV 无法完整表达的文件和非标量字段。
- 用于审计或恢复时，保留校验和或不可变归档。
