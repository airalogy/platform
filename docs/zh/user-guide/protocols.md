# Protocol

Protocol 是可复用、可版本化的研究流程与结构化数据定义。它可以同时包含供人阅读的说明、步骤、检查项、变量、文件和其他有明确类型的输入。

## 查找或创建 Protocol

进入 Project 后，可以看到由该 Project 管理的 Protocol。根据角色和实例配置，你可以直接创建、从示例开始、导入受支持的包，或使用 AI 辅助草拟。生成或导入的内容在用于真实研究前仍需人工审核。

如果界面要求填写 Protocol ID，应使用稳定、清晰的标识。显示名称和描述可以解释科学用途；ID 会用于路由和集成，创建后未必能安全修改。

## 不依赖 AI 和设备的入门练习

在 Project 内选择**新建协议 → 从模板开始 → 首条 Record 练习**，填写易于识别的名称，在编辑器中打开草稿并点击**保存**。确认实验室、项目与版本后再保存。创建 Protocol 需要相应权限；记录者可请 Protocol 负责人为团队准备一次。

中英文练习模板包含两个必填项、示例数值及保存、提交、修订说明。它会创建普通的可编辑、可版本化 Protocol，并非单独的演示模式。练习数据明确标记为模拟数据，请放在练习项目中，不作为科研证据。整个流程不依赖 AI 服务。

## 有意识地修改

修改已经产生 Record 的 Protocol 前：

1. 确认当前版本以及下游工作是否依赖现有字段。
2. 需要保持历史 Record 可比时，优先采用兼容的增量修改。
3. 字段改名、删除或改变类型属于 schema 变化，需要明确审核。
4. 发布或记录前预览渲染结果，并解决校验错误。

AI 可以帮助草拟或解释变更，但负责研究的人员仍应对科学正确性、安全性和最终字段定义负责。

## 复用与 Workflow

只有在流程和数据契约确实相同时，才应跨实验复用 Protocol。科学含义发生变化时，应建立独立 Protocol 或明确的新版本。

启用 Protocol Workflow 后，可以把多个 Protocol 连接为有向研究流程。执行前应检查起始 Protocol、转移关系和数据映射。Workflow 应让交接更清楚，而不是隐藏步骤之间未记录的假设。

## 分享与引用

访问范围由 Lab、Project 和 Protocol 规则共同决定。应通过 Platform 的成员和授权能力分享，不要把未公开内容复制到不受控位置。稳定的 Platform 路由可以用于引用 Protocol，但接收者仍需具备相应访问权限。

角色说明见[协作](./collaboration)，使用 Protocol 采集数据见 [Record](./records)。
