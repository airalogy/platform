# 科研自动化

Airalogy 的科研自动化从有边界的 `Research Task` 开始，而不是从无约束对话开始。一个 Task 会把目标、成功与停止条件、Lab 和 Project、已锁定的 Research Environment、Runs、Actions、Evidence、Claims 及最终人工审核保存在同一条可追溯链路中。

## 开始 Research Task

1. 进入“科研”，在正确 Project 中创建 Task。
2. 填写可检验的目标、成功条件和停止条件；如果 Task 必须在硬性的时间或费用边界内运行，同时设置截止时间和单一币种的预算上限。
3. 选择可能指导或约束研究的 Protocol 版本、数字工具、已审核 Knowledge、Lab 资源类型、已批准的外部科研服务，以及受治理的 Compute Environment。若研究路径只需受治理的数字工具或外部结果，可以不预先选择 Protocol。
4. 预览保存位置与将被捕获的环境，然后确认创建。
5. 开始 Task。Aira 可用时，它会持续推进，直到遇到人工、审批、工具、外部结果或最终审核边界；AI 不可用时，同一 Task 仍可通过明确的 Actions 执行。

AI 可用时，也可先在 **Aira 意图入口**中说明科学问题和可选约束。Aira 只能从你当前有权使用的 Protocol、Tool、已审核 Knowledge、资源、服务和 Compute Environment 中生成可编辑的 Task 简报。这一步不会创建 Task、预留资源、支出资金、下单、运行代码或启动仪器。请检查假设和风险提示，按需编辑所有字段，再走同一套确定性预览和确认流程。AI 关闭时，意图入口自动隐藏，完整手工表单仍然可用。

之后修改 Protocol 或 Knowledge 不会静默改变已捕获的 Research Environment。需要使用新版本时应创建新 Research Task；后续 Run 会按设计继承来源环境。

## 设计版本化 Protocol 工作流

进入 **项目 → 工作流**，添加 Protocol 卡片，为每次执行选择准确版本，并通过画布连线或可编辑列表配置前置依赖。同一 Protocol 可以添加多次：每张卡拥有稳定的独立标识，并分别产生 Record。移动、重排卡片不会改变其身份；单张卡、独立并行和多前置节点汇合均有效。

预览流程、固定版本和保存项目后，确认发布不可变修订。后续编辑产生新修订，不改写已开始的 Run。Workflow 和明确填写的初始值属于项目共享资产，不是私有分析报告；API 会检查当前项目成员及 Protocol 权限。

运行已发布修订时，选择当前项目内的一个**科研任务草稿**，其已捕获环境必须包含每张卡使用的准确 Protocol 版本。没有适合的任务时，先通过原有科研任务表单创建，但不要单独启动。预览并确认 Workflow 运行后，平台将流程编译为普通 Research Actions，仅放行已满足依赖的卡片，并遵循已固定执行者的审批策略。通过原有科研任务工作台完成审批、人员交接、Record 填写、暂停和取消。卡片全部结束后，仍须由人审核普通结果包；执行成功不等于自动得出科学结论。该固定流程不依赖、也不会调用 AI。

在卡片配置中，可以给前置依赖设置一个类型明确的比较条件，字段来自上游 Protocol 的固定 Schema。条件为假表示**未选择该分支**，不是实验失败。汇合会等待所有入边确定；至少一条选中且没有失败时执行，全部未选中则正常跳过。缺值、null、类型冲突或上游失败不会被当作条件为假。

**字段传递**与连线是两回事。需要明确指定直接前置卡片的标量字段及目标字段，类型和单位必须完全匹配，不能覆盖手工指定的初始值。后端读取准确的已提交 Record 修订，封存来源和决策回执，验证目标完整 Schema，再要求一次展示实际输入及来源版本的 Action 审批。Record 后续新增修订不会改变已封存的输入；来源删除、失去读取权限或被篡改会阻止审批和执行。若必需输入来自未选中分支，目标会明确失败，不会借用其他分支的数据。文件引用不是普通文本，不能通过标量传递绕过权限。

能查看科研任务并不代表能读取来源 Record。当前查看者没有某个已解析来源的权限时，新工作流仍显示状态，但限制对应卡片输入、回执和完整结果包的读取。可独立读取的卡片仍可处理，其权限由自身来源和已提交 Record 决定，不受无关分支影响。审批要求能读取该卡片的实际输入，完整结果导出则要求能读取全部来源；脱敏预览不能用于批准执行。

将输出登记为 Evidence 也不会扩大来源权限。Evidence、依赖它的 Claim，以及 Knowledge 中附带的原始证据链接仍按准确来源检查；来源撤权后，这些入口不能绕过私有分析或文件限制。已经显式审核发布的 Knowledge 正文按自身范围授权，隐藏原始证据链接不会撤销已完成的发布。整体 AI 审核、完成确认和结果导出不能省略不可读证据后冒充完整结果。

### 使用固定版本的数据资产

声明有名称的数据输入，将完整文件或明确指定类型的 JSON 字面对象键字段映射到 Protocol 字段。数据输入不是执行卡片，不需要虚构前置节点。运行预览时，为每个输入明确选择当前可读、就绪的 Project DataAsset 及准确版本，不会自动回退到最新版。已有普通 Compute 的输出可经正常审核成为托管资产；该入口不改变论文库仅上传 PDF 的边界。

核对版本、文件摘要、映射值及目标字段，再确认 Run。每个接收输入的卡片仍需确认实际输入。后续资产版本不会改变已固定输入；源文件被归档、不可访问、发生变化或不兼容时会阻止使用。JSON 标量要求明确且匹配的 Schema 与准确单位，不接受任意 URL、猜测的数据值或隐式单位转换。完整文件在 Record 和下载中始终保留来源访问限制。

### 加入可复用分析卡片

从已保存的**内置分析方法**中，将一个准确修订显式发布到所属项目。确认前检查标题、Protocol Schema 和将共享的统计规则。发布会创建独立项目资产，不共享原私有选择条件、Records、报告和 AI 来源；后续编辑私有方法不会改变已发布快照。

使用该已发布方法添加分析卡片，并连线、勾选需要参与分析的全部直接前置 Protocol 卡片。单来源方法要求来源属于同一 Protocol，字段类型与单位兼容；不会沿用方法的历史数据选择，也不会分析整个项目。全部声明来源须提交不同的准确 Record 修订，未选中分支不能让样本量悄悄减少。为每个输出指定名称、字段、统计量；分组方法还须明确填写完整分组值，不隐式采用第一行或第一组。

跨 Protocol 的已保存方法也可发布到所属 Project。逐个输入槽明确选择允许的准确 Protocol 版本，核对版本、字段、单位和目标范围后确认；新增兼容版本不必先生成一条假 Record，但不能改变方法引用字段的类型、单位或枚举含义。发布只共享统计规则和版本契约，不包含历史 Records、问题或报告。

在 Project 分析卡片中，逐槽选择已连线的直接前置卡片。同一槽可接收同一 Protocol 的多次独立执行；一张来源卡片只能使用一次，同一条 Record 不能作为多个样本重复计入。Task 只需固定本次实际使用的 Protocol 版本，不需同时固定方法允许的所有兼容版本。可以选择单个来源的统计量，或显式关联结果的统计量作为命名输出；不选输出则只生成完整报告。审批展示每个槽实际使用的节点、Record 修订及统计预览，全部来源就绪并通过授权后才允许计算。

实际输入解析后，在新一轮 Action 审批中核查准确数量、来源和方法。只有批准才会创建普通后台分析作业。拥有全部输入读取权的成员可以在科研任务内查看计算报告，独立私有报告链接仍仅属于发起人。命名且类型明确的结果可以驱动条件或填入后继 Protocol 字段，后继仍须对实际输入单独审批。暂停会推迟尚未开始的计算，取消任务会丢弃晚到结果且不放行后继。工作流所属分析统一通过科研任务控制，不从独立分析入口取消。

已保存的 Python/R 方法也可显式发布。请检查将共享的代码及常量、参数、输出文件声明、准确镜像/环境修订、完整输入 Schema 和结果 Schema，不要将凭据写入共享源码或参数。可以明确声明方法专用结果 Schema；未声明时使用固定环境的结果 Schema。Platform 不从代码或历史私有数值推断输出契约。每个标量端口选择计算 JSON 内准确的对象字段路径，类型、单位及可空性来自该 Schema；不选端口即可只生成报告。Compute 输入要求完整 Protocol Schema 相同，不只是数值字段同名。

创建科研 Task 时选择方法固定的准确环境修订，不能用新版环境自动替代；一个 Task 对同一环境最多固定一个修订。Run 预览选择有权审批人（默认负责人），采用本 Task 的预算与期限，不沿用原私有分析的审批人或费用设置。唯一一次 Action 审批展示实际解析的 Records、代码和费用，随后既有 Runner 才收到作业。有预算的 Task 要求估价已知且币种一致，预留和用量结算使用普通 Task 账本；执行中断但用量不明时，不会按零费用处理。暂停排队作业会保留原作业，暂停已运行计算则请求停止，不承诺进程断点恢复。查看报告及下载输出复核全部原始输入权限，不能通过第二个私有分析审批入口绕过科研任务治理。

### 传递文件并保留原有访问范围

对直接前置卡片的 `FileId` 字段使用**文件**绑定；也可以明确选择 Compute 方法声明的输出文件，将其命名文件端口连接到下游 Protocol 的 `FileId` 字段。扩展名需兼容；通用来源在解析时按目标限制检查实际扩展名。选中的可选输出文件没有产生时会明确失败。文件不能用作条件、普通文本绑定、任意 URL 或静态初始值。

下游审批同时展示文件名、类型、大小、SHA-256，以及准确的来源 Record 修订或 Compute 结果。平台在目标 Protocol 内创建封存且计入配额的逻辑引用，不移动原文件，也不发布私有 Compute 输出。预览、下载、导出及后续使用都保留目标与原始来源权限的交集；加入目标范围不会自动获得来源权限。短时预览链接打开时仍重新鉴权。受管文件及其源文件元数据不能原地重命名；需要变更时创建新的源文件或修订。支持不超过 256 MiB 的受管上传文件，不将外部存储 URL 当作已验证的文件字节。

Compute 接收封存的 `records.json`；只有已保存方法明确声明的附件字段才会提供文件字节，具体见下文。JSON 中出现 FileId 本身不授予文件访问权。若要将受管理 DataAsset 的准确版本用作 Protocol 输入，请使用上文独立的资源输入流程。数组/对象映射仍为后续工作；跨 Protocol Workflow 分析当前使用内置统计规则，不是任意多来源 Compute 代码执行。

### 明确转换既有旧流程

在项目工作流列表选择**转换旧工作流**，目录仅展示自己有权访问的旧流程。逐个确认每次 Protocol 出现所固定的准确版本，并检查有向依赖；双向连线或循环需要明确调整。确认仅将已审阅的结构创建为新的项目定义：旧自由文本逻辑、默认目标/策略、执行路径、Records 和结论均不复制或执行。预览过期后需重新检查。

确认只创建新的不可变修订，不启动科研任务。原旧 Workflow 的查看与继续入口保留，原对象不变。转换回执仅创建者可读，发布新定义不会公开旧私有逻辑或执行历史。

## 先对已有 Records 做确定性分析

在 Protocol 的 Records 页面选择“分析筛选结果”或“分析选中记录”，也可以进入 Project 的“分析”。筛选入口使用最近一次成功应用的筛选条件，选中入口固定已选 Record 的准确修订，不局限当前页。默认先取最新可读的已提交修订，再筛选；草稿不参与分析。

手工选择数值字段、分组、字段筛选和缺失值策略，预览包含/排除数量、字段单位、缺失与非法值，以及私有保存位置，再确认运行。后台计算会生成描述统计表和准确来源；刷新页面可以继续查看，取消后不会采纳晚到的计算结果。当前内置算子每次最多处理 5,000 条 Records、200 个分组，不执行用户提供的代码，也不把描述统计当作因果或显著性结论。单位或类型不兼容时，请缩小到兼容版本，不要把同名字段当作可直接合并的数据。

已完成报告可以下载 JSON，或将分析方法保存为可修订的方法。方法保留原选择规则；复用时确认本次数据范围，产生新的预览、快照和运行，旧报告不变。报告只对发起人可见，并且每次读取、下载和执行都会重新校验来源权限；撤权后不能凭旧报告绕过限制。选择柱状图或折线图，可查看真实计算的分组均值及有效样本数。不同字段保留独立坐标轴和单位，缺失均值显示为空缺而非零；折线遵循报告分组顺序，不推断时间序列，完整数值表始终保留。

### 请 Aira 草拟或解释分析

AI 可用时，输入问题并明确同意发送界面说明的分析上下文。草拟阶段只发送字段目录与选择摘要，不发送 Record 原始数值。Aira 可以提出内置描述统计算子、请求澄清，或指出需要受治理 Compute 的工作；不会自动执行代码、创建科研任务或运行分析。采用可支持的草稿后，仍可手工编辑，检查输入和影响预览，再确认正常的确定性计算。来源变化时，应重新生成草稿或明确切回手工分析，不会静默扩大选择范围。

报告完成后，可以单独请求结果解释。此时发送问题和已计算统计值，不发送原始数据行。保存的解释将指标引用绑定到真实结果的数值、单位及样本数；文字仍是 AI 建议，不是已验证的科研结论，请对照数值表核查。草稿和解释保存为私有历史，保留模型、问题及输入输出摘要，而不是仅存在于临时聊天中。响应丢失时可读取同一次生成，不重复调用模型；失败后须明确发起新请求。

采用后的草稿即使经编辑或保存为可复用方法，也保留原始 AI 来源；复用历史来源**不代表 Aira 已重新审阅新数据**。AI 关闭时隐藏生成控件，仍可读取当前有权访问的历史，完成手工分析、图表、方法复用和导出。Workflow 分析使用上文独立发布流程；下文多 Protocol 手工分析保留独立的来源与综合判断契约。

### 运行高级私有计算

在同一分析工作区选择“高级计算”，使用经审阅的 Python/R 代码完成内置算子之外的分析。切换模式保留原选中 Records，不会执行任何代码；Aira 指出需要 Compute 时进入此配置。选择实验室已登记的不可变环境修订，填写代码和 JSON 参数、声明结果文件，并选择同时具备 `research.approve` 及全部输入 Record 当前读取权的审批者。发起人还须具备 `research.compute.use`；项目角色不能绕过 Record 级权限。

开启 AI 后，选择环境和语言，再单独同意请 Aira 草拟代码。Masterbrain 接收字段目录、选择摘要和准确环境契约，不接收 Record 原始数值。Aira 可以提供可编辑源码、参数与输出声明，也可以请求澄清；生成不会创建执行任务或授予审批。采用后仍进入普通表单，请核查假设并按需编辑；来源范围或环境改变时，需要新的匹配草稿，或明确返回手工方式。语言、参数 Schema 和输出限制会经过校验，但通过这些检查不代表方法科学有效，也不保证每段生成程序都能成功运行。

确认前检查准确来源数量与摘要、代码、镜像、输入/结果 Schema、资源与网络限制、文件大小、保存位置，以及可选费用和期限。环境预估费用不是服务商实际账单，未知价格也不等于免费；每次运行采用独立审阅的费用上限，不会隐式预留科研任务预算。审批者再次审阅同一契约后，既有 Runner 才能执行。缺少 Runner 或旧 Runner 未声明支持分析任务时不能执行；已授权但离线的 Runner 会使任务等待。状态不确定的运行不会静默重跑，应恢复原 Runner 或请计算管理员检查其状态。

代码从 `AIRALOGY_INPUT_DIR/records.json` 读取封存快照，从 `AIRALOGY_INPUT_JSON` 读取参数，将 JSON 对象写入 `AIRALOGY_RESULT_JSON`；声明的文件写入 `/airalogy/output/files/` 下的准确文件名。快照包含每条 Record 的 `data`、准确来源修订、Schema 和字段定义；字段同名不代表单位兼容。API 进程不执行代码，只有输出大小、结果 Schema、文件回执、费用、当前来源/审批权限和租约校验都通过，才采纳报告。

分析已上传的 CSV 或其他受管附件时，在高级表单中明确添加“Record 附件字段”，并设置稳定的输入标识。目录仅提供在所有选中 Protocol Schema 中明确声明为 FileId 的字段。每条选中 Record 都须为每个声明提供有效文件；附件缺失、类型不支持或超限都会阻止预览，不会静默排除样本。每次最多声明 16 个字段，按选中 Records 展开后最多 30 个实际文件，单件上限 256 MiB、合计上限 512 MiB。重复引用仍保留各自的 Record—文件映射，并计入逻辑数量和字节限制。

确认和审批前，逐项核查来源 Record 修订、文件名、字节数、SHA-256 及只读输入名。代码从 `AIRALOGY_INPUT_DIR/attachments.json` 读取映射，其 `files` 条目包含 `record_id`、`record_version`、`field_path`、`input_id` 和 `mount_name`。按挂载名读取 `AIRALOGY_INPUT_DIR` 下的文件，而不是把 FileId 或存储 URL 当作路径；映射不暴露服务端存储位置。`records.json` 保持原样，未声明附件时不提供附件映射或文件字节。`input.json` 保留给参数，不能作为输入挂载名。

发起人、审批者和 Workflow 接收者均须保有准确来源 Record 与文件的读取权。确认时封存文件字节和来源元数据，不发布为项目 DataAsset；来源变化需要重新预览，受保护文件元数据不能原地修改。保存方法只保留字段声明，不携带历史文件身份或权限；发布时按固定 Schema 校验字段，每次 Workflow 运行重新解析、审批本次实际文件。Aira 不代替用户选择附件，草拟代码时也不接收附件字节。关闭 AI 后仍可手工选择附件；采用草稿后增加附件声明会保留 AI 来源并标记为用户编辑。

报告与文件仍只对发起人可见；审批只展示待审契约，不授予私有结果阅读权。重新读取和下载时会复核原始来源权限，已保留的上传文件计入统一研究文件配额。发放前可以取消，执行中可明确请求 Runner 停止；即使已失去来源读取权，发起人仍能停止自己的任务。收到取消请求不等于离线 Runner 已确认停止。成功计算可保存为版本化方法，每次复用都预览新输入，旧结果和代码保持不变。关闭 AI 后仍可完成这条手工路径。

计算成功后优先展示结果；展开历史执行契约，可核查原始代码和限制。历史 Runner 可用性是当时的快照，不代表当前任务状态。可以单独同意请 Aira 解释程序产生的有界 JSON 结果。结果本身可能包含敏感数值或程序复制的原始输入，这次同意涵盖结果内容而非仅元数据；本功能不会额外读取或发送来源 Record 快照、私有附件或服务端存储标识。每条结果坐标由 Platform 从封存输出解析，引用不存在时拒绝，不用编造的数值、单位或样本数代替。程序输出和 AI 文字都不等于经独立验证的科学结论。结果超出上下文上限时明确拒绝，不会静默截断，可下载后人工检查。代码草稿与解释采用和内置分析相同的私有单次请求恢复与来源历史；AI 关闭后仍可读取有权访问的历史、编辑和复用方法，不另行调用模型。

## 分析同一 Project 中的多个 Protocol

在项目分析工作区选择跨 Protocol 分析。选择 2–8 个当前有权读取的不同 Protocol，为各输入设置清晰标签，分别配置字段、筛选、分组和缺失值策略。每次全部输入合计最多 5,000 条已提交 Record 修订；已保存方法保留原选择，只有明确选择新数据才改变范围，普通分析不要求先创建科研任务或配置 Runner。

没有可靠样本关联时，使用“分别分析、综合证据”。每个 Protocol 保留自身 Schema、单位、计数与统计，不因字段同名而合并。需要联合统计时，首阶段支持两个输入的内连接或左连接，以及一个或多个明确的一对一样本键。确认关联键语义、输出字段含义和单位；类型和单位必须准确匹配，不自动转换字符串/数值、去空格、忽略大小写、换算单位或聚合重复实验。重复键会被拒绝；缺失键需要修正或明确选择排除，预览展示缺失、重复、筛选、排除、匹配及未匹配数量。左连接的未匹配测量不是零。

预览来源、关联影响与私有保存位置后确认，由既有工作器基于固定快照计算。联合结果使用明确的派生行身份，每个字段追溯准确来源 Record 修订，不伪装成新实验 Record。保存、修订方法，再明确预览新数据并创建新运行；比较来源和结果差异不会覆盖旧报告。Protocol 或 Schema 契约改变时，必须明确修订方法。

计算完成后，可记录“支持”“反证”或“无法定论”的人工综合判断，引用至少两个来源输入，并填写局限及未回答问题。Platform 从封存结果解析被引用统计值，每次修改生成独立判断修订，不改变计算结果。运行成功和人工判断均不等于科学验证或 Knowledge 组织审核；JSON 导出包含计算报告及独立封存的综合判断历史。

即使 Project 公开，原报告和方法仍只对发起人可见；显式发布方法才会创建可复用的 Project 副本。读取、重跑、比较、导出均重新检查全部来源及受控文件引用权限。关闭 AI 后仍可完成整个手工流程。已发布的内置方法还可按下节流程形成经过审核的 Protocol 草稿。跨 Protocol Aira 辅助、显式单位转换、重复实验处理及 Compute 方法提升仍属 RFC #6/#9 后续工作，不会隐藏式自动执行。

### 将稳定分析方法整理为 Protocol

先将已保存方法显式发布到其 Project，再从方法发布成功界面或 Workflow 方法控件打开“Protocol 草稿与历史”。目前支持单 Protocol 内置统计和 Project 分析，包括独立综合与明确关联。这里创建的是普通的方法说明资产，不是一次分析运行、实验 Record 或已审核科学结论；已有 Workflow 分析仍通过独立的执行路径运行。

选择“新建 Protocol 草稿”，检查三个完整文件：

- `protocol.toml`：普通 Protocol 的标识、名称、版本及支持的说明元数据，可在保存前编辑。
- `protocol.aimd`：可编辑的方法说明与声明式字段，用于记录真实分析引用、执行说明和局限。可展开“预览 Protocol 内容”检查排版；此草稿路径拒绝可执行赋值器、连接块和自定义模型代码。
- `analysis-method.json`：只读的计算配方及准确引用的字段契约，包括明确的关联语义。不包含原始 Protocol/Version/Record 身份、私有 pipeline 身份、原问题、结果、AI 历史或无关的完整来源 Schema。需要改变计算方法时，先修订并显式发布新的分析方法，不直接修改此清单。

字段标签、枚举和筛选常量仍可能包含科研信息。共享前须检查完整文件及 Project 的公开/私有保存位置；没有复制原始数据，不等于方法适合直接公开。包本身不授予原始输入或报告的读取权。

填写修订说明，预览准确文件及摘要，确认保存位置和共享范围后保存。已保存草稿可重新打开，历史修订只读；仅保有目标写入权限的作者可以编辑。审核通过后再保存修改，会产生新的“草稿”修订并重新要求审核，旧审核不会自动覆盖改过的正文。

审核是独立的明确动作，同时要求科研审批能力与目标 Protocol 的创建或更新权限。同一个人只有具备这些权限时才可既起草又审核，作者身份本身不代表审批权限。核对已保存修订、方法清单和准确包摘要，填写审核意见，再通过或驳回该修订。经过审核后，作者或当前科研审批者可在具备目标写入权限时发布；发布者和审核者都须仍能读取方法的全部来源，系统同时重新检查审核者的审批及目标写入权限。

预览并确认发布后，将在同一个 Project 创建普通 Protocol。创建更高版本时，API 要求明确的目标 Protocol 和准确的当前基线版本；首次发布后，可通过“起草下一 Protocol 版本”选择该目标。保留其标识，在 `protocol.toml` 中明确增加版本号；基线已更新时须重新起草，不覆盖已有版本。Platform 将服务端保存的准确受审包交给普通 Protocol 上传路径解析，返回新 Protocol/版本链接。确认结果不确定时，应重试原确认或重新载入已保存状态，不要另建一份草稿。

发布后的 Protocol 遵循普通 Protocol 访问规则。受保护的方法来源链接仅向仍有来源读取权的人显示；下载包不代表获得来源权限，也不会成为可执行的 Workflow 绑定。只有完成真实分析后才填写说明字段，结果审核仍走独立的 Evidence/Knowledge 流程。整个起草、审核和发布过程无需开启 AI。Compute 方法无论使用 Python 还是 R，暂不支持通过该入口提升；已有受治理的 Compute 执行不受影响。

### 发布选定的分析证据

单 Protocol 或 Project 内置分析成功后，选择“选择要发布的结果”，指定本项目内的科研任务，填写独立证据标题与背景，再选择要发布的字段。每个字段保留全部真实统计和完整分组，不能只挑一个数值。可附带一版准确的人工判断修订，其引用字段须同时被选中。该入口不发布任意 Compute JSON 输出。

预览保存位置、选中统计、样本及缺失计数、单位、关联审计与准确来源版本。预览展示本次复制的完整内容，不包含原始数据行、私有分析问题、方法筛选条件或未选择的判断历史。确认后创建新的不可变发布副本与“待审核证据”，不会重新计算或伪造实验 Record、Action。来源、保存位置或最新判断发生变化时须重新预览；同一确认请求可恢复已保存结果，不重复创建副本。

进入科研任务审核证据。即使只发布部分统计，查看者仍须是能读取**全部原始来源**的任务成员，原报告和方法保持私有。验收证据后创建 Knowledge 候选，编辑正文并完成独立审核。分析派生的 Suggested/Draft Knowledge 仍受来源权限限制；经过组织审核后，正文按 Knowledge 自身范围可见，后续撤销来源权限会隐藏证据链接，但不会抹除已经采纳的正文。新的审核和跨范围发布仍会再次检查来源。整个流程无需开启 AI。

## 请有界 Specialist Agent 提供建议

AI 可用时，可在 Task 的数字工具中加入“询问有界科研 Specialist”。Run 执行中，Aira 可以提议一个 Specialist，也可以围绕同一个科学问题，组成 2–4 个角色不重复的 Panel：文献分析专家、实验设计专家、数据分析专家和科研质疑专家。也可手工选择“增加 Action → 运行科研工具”，选择 Specialist、角色，填写准确问题和期望交付内容。

手工确认前，请核对角色、问题、保存位置和已锁定上下文摘要。确认只会创建建议型 Tool Action；Aira 提议仍停在普通审批边界。每个 Specialist 只能看到同一份固定、有上限的 Task、当前策略、已审核且非 Restricted 的 Knowledge，以及已回传到 Run 的类型化结果快照；不能上网或嵌套调用 Tool。每条发现和建议都必须引用快照中的来源标识，Platform 会拒绝虚构引用。每个 Run 最多接受四个 Specialist Action。Platform 不会自动重复失败的模型调用并再次计费；需要重试时，请先检查失败原因，再有意创建新 Action。

结果是分析建议，不是已验证 Evidence 或已完成工作。工作台会展示角色、置信度、来源标识、不确定性、风险、建议的下一个 Action 类型、模型与上下文摘要。Specialist 不能创建或编辑 Protocol、采纳 Claim、写入 Knowledge、指派人员、支出、下单、运行代码或操作设备。整个 Panel 结束后，Aira 才获取结构化建议，然后回到普通 Planner 和确定性 Action/审批流程。AI 关闭时该工具不可用；手工 Knowledge 审核、Protocol 设计、Compute、Human Work 和所有核心执行路径仍完整保留。

## 安全开启经评估的自主执行

仅选择自主等级不会开启自动执行。符合类型的 Action 只有在三道控制同时同意时才可不经再次审批执行：Lab Research 策略开启该类别；精确 Executor Binding 以及技术、风险、费用和时间限制允许；未过期的已评估授权严格匹配 Capability 版本和 Executor 摘要。当前可准入类型包括内部只读 Tool、被动类型化 Wait Event，以及低风险且禁止网络的 Compute。人员、Protocol 工作、结构化 Human Work、仪器、资源承诺和外部服务下单仍需审批。

Lab Owner 和 Manager 可从 Project Research 打开“Research 策略”管理这些控制：

1. 先保持受监督执行。手工运行该精确能力，或审批该精确 Aira 提议，至少完成 5 次。
2. 打开评估候选，检查 Capability 版本、Executor 摘要、近期 Action ID、执行结果和输出回执。Platform 最多取该目标最近 10 个已终止的受监督 Action，样本需至少 5 次完成且没有失败或取消。
3. 选择授权允许的自主等级，设置不超过一年的到期时间，填写治理理由，检查预览后再确认。
4. 需要使用新授权时，创建新 Research Task。已有 Task 和后续 Run 保留当时捕获的策略与授权快照；Action 评估时仍会检查授权是否到期。

Capability 版本、Executor 引用或摘要变化后会成为新目标，必须重新积累受监督历史。当前样本含失败或取消时，候选会继续保持不合格，直到之后的合格样本满足规则。续期也会重新评估并经过“预览 → 确认”。撤销授权会将它从未来 Research Environment 中移除，但不会改写已有 Run；如需立即干预，请暂停或取消受影响的 Run。没有显示候选时，请先在人工审批下完成符合类型的 Action。AI 关闭时，相同手工 Action、策略管理和审计历史仍然可用。

## 登记 Compute Environment

具备科研计算管理权限的 Lab 成员可进入“实验室资源库 → 计算环境”。先填写稳定环境标识，再声明不可变 OCI 镜像摘要、运行时与允许语言、CPU/内存/GPU/超时/输出硬上限、网络策略、输入/结果 JSON Schema、软件清单、风险和可选每小时成本。确认前先预览完整契约。修订会创建新的不可变契约；已有 Research Task 继续固定原修订。

具备科研计算使用权的 Task 创建者可以在创建 Task 时选择已启用环境。Platform 会把准确修订复制到 Research Environment。仅选择环境不会执行代码、预留预算，也不表示存在合资格 Compute Runner。

## 登记 Compute Runner

Lab 计算管理员可以在“实验室资源库 → 计算环境”中新增 Runner、仅一次获取其凭据，并设置硬性并发上限。在独立监管的主机上安装 `apps/compute-runner` 参考进程，推荐使用专用 rootless Podman 账号；配置 Platform 地址、一次性 Runner 凭据、不可变辅助镜像摘要、私有持久状态路径，以及由基础设施独立强制执行的准确出站网络。目录内 README、环境变量示例与 systemd 服务给出完整契约。不要向 Platform 暴露容器运行时 Socket，也不要让无关服务共用 Runner 身份。

Runner 只有在报告非 root 执行、只读根文件系统、网络隔离和无宿主机挂载四项控制时才显示为已就绪。必须逐一把 Runner 绑定到允许执行的准确环境修订；新修订需要重新审核和绑定。停用 Runner 或移除绑定会停止后续工作，但不会删除审计历史。仅登记和绑定仍不会执行任何代码。默认 systemd 服务只允许 CPU；GPU 主机除了 Platform 资源审批外，还需要经过审核的设备专用服务覆盖配置。

## 申请计算

在活动 Task 中选择“运行计算”，从 Task 已固定的准确环境修订中选择一项，再选择允许的语言。输入源码和满足环境输入 Schema 的 JSON；还可以选择同一 Project 内已就绪 DataAsset 的准确版本，并为每项设置安全挂载名。预览前需先声明每个输出文件：填写安全文件名、DataAsset 名称、资产类型、媒体类型、字节上限及是否必须产生；源码必须把这些文件写入 `/airalogy/output/files/` 下。预览保存位置、源码摘要、不可变镜像、资源与网络限制、输入版本、输出、合资格 Runner 数量和最大预估成本，然后确认请求。

AI 开启时，Aira 也可在下一 Action 边界提出同一种 Compute Action。它只能选择 Task 已固定且有授权 Runner 支持的环境修订，以及 Platform 在规划上下文中明确暴露的合资格 DataAsset 当前版本。Aira 会提供受限源码、符合 Schema 的输入和完整输出声明，然后 Run 停在普通审批边界。打开审批影响后，应核对完整源码、摘要、准确输入、限制、成本上限和输出；如需更改任何部分，应创建新提案或人工请求，不会直接改写待审批契约。

确认只创建审批，不会直接执行代码。获授权人员批准准确影响后，Platform 才会为有预算的 Task 预留最大成本并排队。一个受独立监管、与协议兼容且明确绑定该环境修订的 Runner 必须在线；它会主动领取签名短租约，只下载固定输入，在 Platform API 进程之外运行，并回报心跳、结果、申报用量或失败。源码从 `AIRALOGY_INPUT_JSON` 和 `AIRALOGY_INPUT_DIR` 读取输入，并必须向 `AIRALOGY_RESULT_JSON` 写入一个 UTF-8 JSON 对象。参考 Runner 会丢弃不受信任的标准输出以执行存储边界，需要保留的有界诊断应写入结果对象。执行停止后，Runner 只会测量并上传事先声明的文件。Platform 校验结果 Schema、硬性用量上限、媒体类型、字节数和 SHA-256 回执，然后原子地将有效文件登记为 Project 可见的 DataAsset 草稿，保留准确来源。草稿在标记为已就绪或作为已验证 Evidence 使用前仍需审核。Platform 依据实测墙钟时间结算实际成本，并保留完整状态轨迹。需要停止时使用“取消计算”并填写原因；已经交付的作业只有在 Runner 确认后才真正取消，失败或未完成作业已上传的文件不会成为可访问资产。

Platform 不接受 Runner 提交的任意文件系统路径作为资产。新增或更改输出必须重新预览和审批，因为输出声明是签名作业契约的一部分。

## 登记外部科研服务

拥有科研服务管理权限的 Lab 成员可进入“实验室资源库 → 外部科研服务”。先通过“预览→确认”添加服务商，再添加一项或多项服务。每个服务修订会记录准确版本、请求/结果 JSON Schema、风险、是否需要报价、可选目录价与币种、SLA 目标、样本要求、物流规则和条款。修订服务会创建新的不可变契约，不会改写已有 Task。

拥有服务使用权的 Task 创建者可在创建 Research Task 时选择已启用服务。Platform 会把准确服务商和服务修订复制到 Research Environment。这一步只授权能力边界，不会下单、预留预算、发送样本，也不表示已存在结果。

## 申请并接收外部科研服务

在活动 Task 中选择“申请外部服务”，从已锁定服务中选择一项，并填写符合锁定输入 Schema 的 JSON 请求；预览后确认。需要报价的作业会等待服务管理员登记服务商报价，使用目录价的作业则直接生成报价。两种方式都会针对准确的服务商、请求、契约修订、报价、金额和有效期创建独立下单审批。只有审批通过，Platform 才预留预算并把作业改为已下单。报价过期、契约状态变化、预览过期、币种不符或 Task 预算不足都会阻止下单。

履约期间，服务管理员可登记服务商订单号和进度。每次样本交接使用“记录交接”，选择有权访问的 Lab 资源和可选容器，并填写双方、时间、地点、承运方和物流编号。交接事件是不可修改的审计节点；库存消耗仍应另行写入权威资源账本。

服务商返回结果后，先在当前 Task 创建或上传相关 DataAsset。选择“接收结果”，填写结果 JSON、选择准确的 DataAsset 版本并确认实际费用。Platform 会按锁定的结果 Schema 校验，拒绝高于已批准报价的费用，把预算预留结算为实际支出，完成 Action，并把类型化结果交回 Aira。登记失败会释放报价预留，并把 Run 交回 Aira 或普通人工控制。AI 关闭时，请求、报价、审批、交接、进度、结果、费用与操作者历史仍完整保留。

## 从 Paper 形成 Suggested Knowledge

进入“Knowledge”，选中一篇 Paper，先检查元数据、笔记、可见范围和可用全文。你始终可以选择“从论文创建 Knowledge”手工编写；AI 可用时，可选择“用 Aira 生成候选”，系统只会使用你当前有权读取的论文内容生成一份可编辑候选。

请在普通 Knowledge 编辑器中检查候选类型、标题、内容、标签、假设与风险。保存时会先对准确位置和编辑后内容生成预览，再确认为普通、可修订的 Knowledge 资产。Platform 会重新检查 Paper 与文件权限，过期或来源变更的生成结果会被拒绝。Project/Lab 结果初始为“候选”，只有经单独授权的人员执行“审核并采纳”后，才会成为组织已采纳的 Knowledge；Personal 结果因不存在组织审核状态，会在你确认后成为私有草稿。两者都会显示 Aira 来源，编辑不会改变原始生成快照；Restricted 来源不会因此扩大权限，后续发布会创建带来源关系的新范围资产，而不是移动原对象。AI 关闭时，Aira 按钮自动消失，手工路径仍完整可用。

## 从 Knowledge 生成 Protocol 草稿

进入“Knowledge”，切换到“Knowledge 笔记”，在有效条目上选择“生成 Protocol 草稿”。先核对固定的来源修订，选择符合范围的目标 Project，再进入 Aira 草拟。Platform 会通过受保护接口把 Knowledge 内容载入可编辑生成器，不会把正文放进 URL。检查并修改生成的 AIMD 后，选择“保存 Protocol”，再次确认目标 Project。

只有完成最后确认，Protocol 才会成为正式资产。保存时 Platform 会重新检查你是否仍可读取 Knowledge、是否能在 Project 创建 Protocol，以及来源是否仍是同一修订。来源发生变化、归档、被取代、跨范围或不可访问时都会拒绝保存，不会静默生成失去来源的资产。保存成功的 Protocol 版本保留不可变 Knowledge provenance。AI 关闭时不显示这个入口，但模板、复用、导入和手工创建 Protocol 仍完整可用。

## 将已校验结果整理为候选 Knowledge

在 Research Task 中，先把 Record、准确 DataAsset 版本或已完成的结构化 Action 输出登记为 Evidence，并由有权人员完成校验。对于 Action 输出，将 Evidence 来源选为“Action 输出”，选择已完成 Action，检查它的摘要绑定不可变快照后再确认。新 Evidence 初始为待审核；Platform 绝不会把执行成功等同于科学校验。在“科研结果资产”中选择“提议为 Knowledge”，写下可复用的发现、方法、决策或笔记，并选择一条或多条已校验 Evidence。检查 Project 保存位置和准确来源集合后再确认。

对于内置分析结果，先在私有报告中选择“发布分析证据”，预览选定的真实计算结果与保存位置，明确确认后创建独立的不可变副本。新 Evidence 须由有权人员完成校验，才能用于 Knowledge；这一步不会共享私有原报告。

Platform 会创建 Project 范围的可编辑 Suggested Knowledge，并保留不可变 Evidence 快照和版本关系；它不会宣布该候选已经成立或被组织采纳。进入 Project Knowledge 可继续修订，Knowledge Reviewer 评估证据后再使用独立的“审核并采纳”操作。待审核、已拒绝或非 Record、DataAsset、不可变 Action 输出、显式发布分析副本来源的 Evidence 不会出现在可选列表中。该确定性路径在 AI 关闭时仍可完整使用。

## 从已校验 Evidence 生成科学 Claim 草稿

在“科研结果资产”中选择“添加 Claim”，先选择用于界定科学上下文的 Evidence。你始终可以手工填写判断、置信度、不确定性和 Evidence 关系。AI 可用且所选条目都已校验时，可选填写希望比较的问题或约束，再选择“让 Aira 生成草稿”。

Aira 必须评估每一项所选 Evidence，包括与主要判断冲突的反证，且只会返回可编辑 Suggested Claim。预览确认前，请检查并按需修改判断、置信度、不确定性和证据关系。Platform 在生成后和确认时都会重新校验准确 Evidence 及来源版本。签名凭据一小时后过期、不能重复确认，且 Evidence 选择变化时原草稿会被清除。即使修改草稿，原始生成内容仍保留在来源记录中。Aira 不能采纳 Claim，只能由获授权人员另行审核。AI 关闭时，同一手工 Claim 与审核流程仍可使用。

## 用已校验 Evidence 改进 Protocol

在“科研结果资产”中选择“提议改进 Protocol”。选择已固定到当前 Task 的 Protocol，说明科学依据和具体建议改动，并关联已校验的 Record、DataAsset 或不可变 Action 输出 Evidence。确认前先预览准确 Project、Protocol 基线版本和不可变 Evidence 快照。此时只创建建议，不会修改 Protocol。

具备科研审批权且能更新该 Protocol 的人员必须先检查并采纳建议。审核后选择“创建新版本草稿”，在普通 Protocol Editor 中编辑复制的基线包。保存时选择高于当前 Protocol 的版本号并确认完整包。Platform 会在锁内重新检查已审核建议、Evidence 来源和基线版本。如果期间已发布另一版、建议已变化或已被应用，保存会中止，必须针对最新方法重新提议。成功保存会把建议标记为已应用，并关联到准确的 Protocol 新版本；既有版本和活动 Run 都不变。这条完整路径在 AI 关闭时也可用。

AI 可用时，请先选择目标 Protocol 和 Evidence，可补充希望 Aira 关注的重点或约束，再选择“让 Aira 生成草稿”。预览前请检查并按需编辑返回内容。签名生成凭据一小时后失效，确认后不能重复使用；科研上下文发生变化时应重新生成。Aira 不会代替专家审核，也不会直接应用 Protocol 版本。AI 关闭时，全部手工字段和后续流程仍然可用。

## 重试、复现或延续 Run

当前 Run 和 Task 完成、失败或取消后，在 Task 页面选择“新建 Run”。已形成的科学结果必须先经人工审核，才能开启下一次 Run。可选择任意已结束的来源 Run，标记为重试、复现或延续研究，并说明这次执行预期产生的差异。确认前的预览会展示新 Run 序号、来源、保存位置和准确的 Research Environment 摘要。

新 Run 会保留之前每次执行和科研资产，并精确继承来源环境。它不会自动采用之后更新的 Protocol、Knowledge、Tool、执行策略或资源定义。Task 会回到草稿状态，由用户明确启动下一次执行；原截止时间和共享预算账本继续生效。Run 来源链会保留每次结果和人工审核结论，便于对比。

当 Run 关系为“复现”时，最终审核会增加必填的复现评估。只能在界面中显示的来源 Run 与复现 Run 已校验 Evidence 之间比较：选择总体结果，按原定义逐项评估成功标准，说明每项理由，并记录偏差和局限。确定性结果至少需从两次 Run 各选一项 Evidence。来源链变化、Research Environment 不一致、成功标准缺失或乱序、Evidence 属于错误 Run 都会被 Platform 拒绝。证据不足时可判断为“无法定论”，但仍需说明原因。确认后，Run 来源链会显示复现结果，不可变 Result Package 保存完整比较。

## 选择正确的 Action

Lab Owner 和 Manager 可在 Project Research 中打开 **Executor Binding**，治理准确的 Protocol、结构化 Human Work 契约、Tool 版本、Instrument 命令修订或外部服务 Offering 版本。人工工作可绑定未来 Task 负责人、合资格的具体成员或已验证技能池；Instrument 命令始终绑定其登记 Gateway，外部服务始终绑定其登记服务商，两者都保留人工审批。Binding 可禁止后续使用，也可限制 Project、自主等级和每次 Run 的 Action 数。每次变更都经过预览与确认，只影响之后固定的环境或动态 Action 预览，不会改写已确认 Action。

- **Protocol 工作**：把锁定版本的方法指派给人员。Lab 管理员可在“Executor Binding”中将对应 Protocol 版本配置为未来的 Task 负责人、当前 Project 中具备执行权的具体成员，或已验证技能池。在其中打开“人工 Executor 档案”，可记录成员可用时段、并行工作容量、技能等级、验证状态和资质到期时间。技能匹配会从满足全部必需技能和当前 Project 权限的人员中，选择归一化活跃工作量最低者，再将该人员和匹配证据固定。执行人使用正常 Record 表单完成实验，校验通过的 Record 会回传为 Evidence，而不是普通对话消息。Platform 会在派发时加锁并复核成员身份、权限、技能、可用性和容量。AI 关闭时，管理员仍可配置相同绑定，用户也可手工指派 Protocol 工作。
- **结构化 Human Work**：承载不属于可重复科学方法本身的观察、采集、协调或审核。创建时定义类型化字段、完成标准、Evidence 类型和允许关联的准确 DataAsset 版本数量，并在确认前预览保存位置与执行人。执行人填写生成的确定性表单、预览不可变提交并确认；之后必须由 Task 负责人或获授权 Research 审批人接受或退回修改。接受才会生成已校验 Evidence 并释放依赖它的下游 Action，Aira 不能验收自己提议的工作。若活动在定义实验“如何做”，应改用 Protocol 工作。
- **待处理通知**：集中呈现新分配的 Protocol 或结构化 Human Work、等待审核的工作和审批请求。打开后会标记提醒为已读，并进入对应的权威工作页面。部署管理员启用 SMTP 后，Platform 还会发送可重试邮件提醒；邮件等待发送、未启用或发送失败都不会移除站内事项，也不会阻塞执行。
- **科研工具**：运行白名单中且锁定版本的数字能力，例如检索已审核 Knowledge、检索文献或可选的 DOI 元数据解析。输入和输出都会经过 Schema 校验，执行有超时、重试和完整留痕。当多个只读检索确实彼此独立时，Aira 可创建包含 2–4 个 Action 的有界并行前沿；当某项检索必须等待另一项时，Aira 可改为创建包含 2–8 个 Tool Action 的无环依赖图。下游节点可从直接前置的结构化结果接收已声明参数；工作台会标出这些绑定，Platform 会记录准确来源回执，再校验最终参数。只有就绪且有效的节点才会请求审批或执行；前置失败、被拒绝或绑定无效时，下游节点会明确被跳过。只有整个并行前沿或依赖图结束后，Aira 才会重新规划。
- **等待外部结果**：在人员、设备或外部服务返回结果前，把 Run 暂停在类型化边界。选择并确认预期结果契约；系统生成的事件键是不可变的交付引用，当前版本由获授权用户在工作台登记已收到的结果。
- **预约资源**：从 Research Environment 已固定的资源类型中解析具体资源。库存预约需选择容器、准确数量、UCUM 单位与可选失效时间；设备预约需选择时段。Platform 会预览当前可用量与策略，拒绝过期或冲突的确认，并把权威库存预约或设备预约关联到 Action。

Aira 可以请求固定的资源类型、数量、单位或设备时段，但不能任意选择隐藏资源或直接完成预约。Platform 会确定性选择请求人有权使用的候选，并展示准确影响供用户审批。如果审批前库存、权限、资源修订或设备时段发生变化，旧提案会被拒绝并要求重新规划。

需要登记实际库存使用时，在正常 Record 表单对应的资源字段中选择该预留，并提交通过校验的 Record。Platform 会原子地从库存和待消耗预留中扣减用量；部分使用会留下余量给之后的 Record，全部使用则将预留标记为完成。Research Task 会展示不可变的消耗历史，并链回每条准确 Record 修订；重复提交不会二次扣减库存。

对于受治理的 Sample，可先登记 `resource_definition` Protocol 并开启其 `sample` 能力，也可从内置“科研样本”模板开始。资源定义负责学科字段，通用资源账本继续负责稳定身份、Restricted 访问、修订、批次、容器、位置和数量。打开某个样本资源，选择“新增样本谱系”，可将上游样本标记为派生、分装、分割或合并来源。确认前请核对准确的上游、下游、修订与影响。Platform 要求同时具有双方样本权限，会拒绝循环和非法直接来源，并将理由保存为不可变事件。Record 自动生成的谱系也在同一视图中展示。如果物理数量发生变化，还须单独使用库存转移、消耗或报废。

## 注册 Instrument Gateway

Lab Owner 和 Manager 可进入“实验室资源库 → 设备网关”建立本地设备安全边界。创建 Gateway 时先预览影响、再确认，然后把仅显示一次的密钥复制到实验室内网的 Gateway 进程。Platform 之后不会再显示该密钥。轮换操作会使旧密钥立即失效，恢复设备作业前必须先更新本地进程。

从 `apps/instrument-gateway` 安装并以服务方式监管参考进程；密钥应放入本地服务管理器而不是源码，持久状态目录必须设为私有。配置 Platform 的 `/api` 地址、密钥、本地安装的适配器名称、适配器配置和状态路径，生产连接必须使用 HTTPS。内置 `mock` 适配器仅用于联调；真实设备适配器必须独立允许准确指令版本，通过 `preflight` 读取当前安全联锁，并实现幂等安全停止，只有设备确实进入安全状态后才能返回。

选中 Gateway 后，只添加它确实可执行的指令。每条指令必须选择一个有效的具体设备 Resource，固定当前修订，并定义带版本的标识、输入/结果 JSON Schema、风险、超时、设备端确认要求和硬件安全契约。联锁使用由适配器定义的稳定标识，例如 `lid.closed` 或 `temperature.safe`；适配器必须在启动前即时证明每个必要联锁。契约还可要求现场人员和紧急停止。中高风险指令必须在物理设备端确认，高风险指令还必须同时要求现场人员和紧急停止。Schema 或安全契约变更会生成新的允许清单审计修订，已完成的 Job 历史保持不变。停用指令或 Gateway 即可阻止之后的作业领取。

升级时，已有高风险指令和排队作业会自动获得现场人员与紧急停止要求。恢复这些作业前必须先更新本地适配器；Gateway 在返回符合要求的即时证明之前，Platform 会保持拒绝执行。

## 运行科研设备

创建 Research Task 时先固定相关设备 Resource 类型，并在 Lab 资源库中创建或获得一条分配给你本人的已批准预约。在活动 Task 中选择“增加 Action → 运行科研设备”，选择白名单指令和你本人的已批准预约，以 JSON 对象输入指令参数；确认前必须预览准确指令修订、设备、预约时段、风险和设备端确认要求。

作业会排队到预约时段开始。本地 Gateway 主动领取签名短租约，校验准确本地适配器，执行已固定的安全预检，并在启动前把有上限的证明发送给 Platform。任一必要联锁缺失或未通过时，作业将在设备启动前失败。之后 Gateway 在需要时于设备端确认，执行中持续心跳，并回传由 Platform 依据已固定输出 Schema 校验的结果。工作台会将安全契约和留存的证明与交付尝试、最后心跳、结果和失败一同显示。必要时填写原因并选择“请求停止”；已交付作业只有在 Gateway 确认后才算已停止。暂停或取消 Task 也会对已交付的物理工作发出停止请求。Platform 绝不自动重试物理操作；恢复 Run 前必须先检查设备。

需要经审核的多步设备过程时，选择“增加 Action → 设备控制会话”。选择一条已批准预约，再选“有界序列”或“反馈循环”。可添加 1–20 个步骤模板；每步都需稳定标识、可用指令、JSON 输入对象和明确下一目标：另一步骤、完成或暂停。有界序列不允许成环。反馈步骤可以用固定 JSON 值比较一个结果字段，并选择条件为真或为假的目标；预览前必须设定最大执行次数和时间。只有当预览显示的设备、Gateway、预约、风险、步骤数和上限都符合预期时才确认。

Aira 可用时，先选择预约和上限，然后在“用 Aira 起草控制过程”中描述目标，并选择草稿最多包含多少步。Aira 只能使用当前预约下已显示的指令。结果会填入同一编辑器，仍可任意修改；生成草稿不会创建会话或发送指令。逐项检查参数和转移后，再使用与完全手工草稿相同的确定性预览与确认。AI 关闭或不可用时，该面板会消失，完整手工构建器仍保留。

Platform 每次只释放一步。只有上一个 Instrument Job 返回符合 Schema 的结果，且权限、固定项、Binding、预约状态和上限仍全部通过时，系统才会创建下一步。后续高风险步骤会显示“复核并继续”，不能被首次整体确认概括授权。会话活动或待复核时，同一控件可“停止控制会话”。指令过期、比较无效、达到上限、遇到明确暂停目标、失败或停止时，Platform 都不会猜测或重试；工作台会保留准确会话状态和原因，等待人工复核。构建器和所有控制在 AI 关闭时仍完整可用。

## 控制时间与预算

Task 页面会显示已固定的截止时间，以及预算的预留、实际支出、已承诺和剩余金额。具备科研审批能力的用户可以登记预留、释放、支出或冲销；每条记录都必须基于当前 Task 修订先预览再确认，保存后不能修改。释放不能超过已有预留，冲销不能超过已有实际支出；需要纠错时应追加抵消记录和正确记录，不能改写历史。

已批准的截止时间或预算上限需要变化时，选择“修订运行边界”。填写完整的新边界和修订原因，预览新旧值后，基于当前 Task 修订确认；每次修订都会成为不可变的 Task 事件。已有账本记录的预算只能调整上限，不能移除或更换币种；降低后的上限必须高于已承诺总额。若旧边界已暂停 Run，修订只会让它恢复为“可继续”，不会自行重启；请先检查 Run 状态，再单独选择“恢复”，避免治理变更直接触发执行。

Platform 会在 API 层创建每个新的人工或 Aira Protocol、Tool、Wait、Resource、Instrument、External Service 或 Compute Action 前检查限额，拒绝过期预览和超限写入。确认的预算记录耗尽上限时会立即暂停 Run；从其他入口发现截止时间或预算到达边界时，会在下一个运行边界安全暂停。已批准 External Service Job 会预留准确报价，已批准 Compute Job 会预留最大运行时间估算；两者完成时都会把预留转换为经校验的实际成本。模型提供方返回的费用若与 Task 币种一致，Platform 会幂等记为实际支出；如果该支出耗尽上限，将在应用模型响应前暂停 Run。没有费用数据或币种不同时，用量事件仍会保留，但需手工登记支出；Platform 不会虚构模型价格或汇率。

检索候选项只是 Action 输出。Platform 不会将其静默采纳为 Knowledge、Evidence 或 Claim。

每次到达“下一步做什么”的边界时，Aira 会先在固定版本的 Protocol、可用 Tool、固定的资源需求、符合条件的 Instrument 指令、固定的 External Service、类型化外部 Wait 与结束当前路径之间选择。只有你拥有已批准且未过期的设备预约时，对应设备指令才会向 Aira 显示。模型只选择列表中的指令 ID 和输入参数；Platform 确定性选择预约，并把准确指令、设备、时段、风险和本地确认要求作为普通审批展示。批准前任何 Instrument Job 都无法被 Gateway 领取；指令、权限、预约过期或预约被其他作业占用都会让批准失败关闭。

对于 External Service，Aira 只能选择已固定到 Research Environment 的准确服务，并生成符合固定输入 Schema 的请求草稿；这不等于已下单。Platform 会创建与手工路径相同的受治理 Service Job：需要时由服务管理员登记服务商报价，每个准确报价都会生成绑定摘要的下单审批，预算预留、样本交接、履约和结果接收仍由确定性界面控制。Action Planner 不会直接执行模型自由文本：Platform 会先校验 Action 类型、白名单、固定版本、输入参数、资源需求和结果契约，再创建正式 Action。物理 Action 和服务下单始终需要审批，其他 Aira Action 则继续按对应准确风险策略治理。

Aira 也可将固定版本的 Protocol Run 或结构化 Human Work 放入混合依赖图。创建计划图不会立即派发实验工作；Platform 会等待全部前置条件，重新校验固定的人员 Executor Binding，进入普通审批，通过后才创建 Human Work Item。Protocol 执行人使用现有 Record 表单完成工作；只有准确 Protocol 版本、提交者和 Record 全部校验通过后，下游工作才会开始。通用 Human Work 执行人填写固定生成的表单，并且只能关联准确的当前 DataAsset 版本；提交还须经有权人员接受，才能成为已校验 Evidence 并释放下游 Action。其他已就绪分支可并行继续，但整张图稳定前 Run 不会重新规划。

已完成的 Human Work、Tool、Instrument、Resource、External Service、Compute 和外部 Wait Action 会把类型明确的结果回传给后续 Aira 规划与结论，Platform 只保留有上限的近期结果窗口。已接受的 Human Work 提交已经通过明确的审核门禁，会直接登记为已校验 Evidence；其他结构化输出仍须经预览和确认登记为待审核 Evidence。Platform 会封存只可追加、由 SHA-256 绑定的快照，在 Task 结果包中呈现，且在它支持 Claim、Knowledge 候选或 Protocol 改进前仍需人工校验。这些路径不依赖 AI。

## 提交外部结果

打开正在等待的 Action，选择“提交结果”。填写固定事件契约定义的字段，预览准确载荷后再确认。Platform 会检查当前用户权限、事件类型、载荷 Schema 和事件修订号，过期、重复或不兼容信号会被拒绝。

AI 可用时，Run 随后恢复 Aira；AI 关闭时，它会回到普通手工控制，不阻断 Protocol、Record、Knowledge 或结果审核。

## 审核科学结果

执行成功不等于科学结论成立。完成 Task 前：

- 检查执行账本和失败尝试；
- 校验或拒绝待处理 Evidence；
- 根据关联 Evidence 和不确定性审核 Claims；
- 完成或取消尚未结束的 Actions 与审批；
- 记录目标评估、科学结果和审核后的结论。

AI 可用时，可选择“运行独立审查”，让与执行 Agent 分离的 Reviewer Agent 评议当前准确结果上下文。请检查它的建议、支持与反驳 Evidence 数量、不确定性、缺失检查和风险提示。对复现 Run，它还会按同一结构草拟逐项复现评估，且只能引用界面中两组 Evidence。只有希望把这些建议复制到可编辑的人工审核表单时，才选择“作为审核草稿使用”；按需修改后，由你自行确认。建议不能直接完成 Task，科研上下文变化后会过期，并作为不可变的建议记录保留。AI 关闭时，可直接完成相同的人工审核和复现评估，不依赖该面板。

确认后，“结果包”面板会展示该次 Run 经人工定稿的准确快照。打开后可核对摘要、定稿时间、科研目标、成功标准、审核结论和资产数量。需交给其他系统时下载完整结构化 JSON，需阅读和移交时下载 Markdown；两种导出都包含同一摘要和完整机器可读快照。旧结果包会标记为“未封存的历史结果包”，兼容读取不代表它具有不可变保证。

取消 Task 会保留已有 Records、Action 历史、工具来源与科研资产，同时防止未完成工作重新启动该 Task。尚未释放的库存预约及待审批或已批准的设备预约会自动归还；提前手工释放同样采用“预览→确认”。

## 权限与安全

Research Action 同时使用当前 Project 与资源权限，并由 API 强制执行。看到工具或资源类型，不代表可以绕过 Knowledge 可见性、Restricted 内容授权、对象级资源访问、库存操作权、设备预约权或 Project 访问权。外部结果必须由具备科研执行权限的已登录用户提交，事件键本身不构成授权。拒绝 Aira 提案后，对应的类型化执行记录会被取消，拒绝原因会记录并传回下一轮规划。
