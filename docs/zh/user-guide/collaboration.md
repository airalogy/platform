# 协作

Platform 的协作遵循 Lab、Project、Protocol 与 Record 的归属层级。界面通过展示或隐藏操作帮助用户理解当前范围，真正的访问控制由后端逐项执行。

## 在正确的范围内工作

- 用 Lab 管理长期成员关系和治理。
- 用 Project 划分明确的研究目标或协作边界。
- 将 Protocol 放在实际承担其科学维护责任的 Project 中。
- 将 Record 存在拥有该研究工作的 Protocol 和 Project 下，不要依赖个人账号传递文件。

## 角色

Lab Owner 负责实验室最高层级设置和所有权操作，Lab Manager 承担被委派的管理工作，Member 在获得访问的资源中工作。Project 和结构化 Lab 还可以提供更细的角色与授权。

能查看上级资源，不代表可以编辑所有下级内容。反过来，界面没有按钮也不是安全边界；后端会按有效角色和资源范围判断每个受保护操作。

## 谨慎邀请与交接

邀请成员前，应确认对方身份、所需的最小角色以及实际需要访问的 Project 或组织范围。只需参与一个 Project 的任务，不应授予全 Lab 管理权限。

交接工作时：

1. 确认相关 Protocol 版本和 Record 都已保存在共享范围内。
2. 记录待办事项和已知数据质量问题。
3. 通过受支持的控制转交所有权或管理责任。
4. 先验证接收者可以访问必需资源，再移除原维护者。

## 链接与公开资源

复制 Platform 链接不会改变资源的访问规则。缺少有效权限的接收者无法看到受保护内容。公开 Project 或 Hub 中只能放入已经获准公开的信息。

Lab Owner/Manager 可继续阅读[实验室管理指南](../lab-admin/)。
