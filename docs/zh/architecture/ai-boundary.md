# Platform 与 Masterbrain 的 AI 边界

Platform 的内置模型调用统一通过正式发布的 `masterbrain==0.12.0` Python 包完成，包括文本向量。默认包模式不要求单独部署 AI 服务。统一的是模型能力入口，不是把整个科研系统移入 Masterbrain。

| 层级 | 职责 |
| --- | --- |
| Masterbrain | 可复用 AI 能力、供应商客户端、模型请求和响应校验、逐次调用用量事件。 |
| Platform | 身份、权限、可信上下文选择、运行预算、审批、持久化资产、审计和执行状态。 |
| Instrument Gateway / Compute Runner | 明确授权的执行，以及独立的结果和停止状态观测。 |

依赖 Platform 业务对象的提示词和上下文组装仍保留在 Platform。模型输出不能授予权限、自行审批、写入正式资产或授权设备操作。离线回归检查禁止 API 产品代码直接导入模型供应商 SDK；统一从 `app/libs/masterbrain.py` 接入。用户提供的 Protocol 执行代码属于独立执行边界，不属于内置模型能力。

## 向量与非 AI 检索

- 保持现有索引契约：Qwen `text-embedding-v4`、1024 维、每次最多六段文本。仅修改模型配置会混用不兼容的向量空间，更换模型必须明确安排索引重建迁移。
- Protocol、讨论索引、公开 Hub 检索和聊天检索使用同一 Masterbrain 向量接口。请求携带服务端生成的用量上下文；交互入口传入经过授权的用户及 Lab/Project，内部 Hub 检索标识为内部服务，不虚构用户身份。
- `AI_ENABLED=false` 会阻止向量模型请求。仅配置 GPT 时不会自动改用 OpenAI 向量模型。缺少 Qwen 能力、模型故障或返回无效向量时，仍保留本地关键词路径。
- 只有关键词的分段使用空向量字段，不伪造零向量或相似度。数据库升级保留已有真实向量，AI 恢复后仍能检索到只有关键词的分段。
- 单个资源索引的删除与写入在同一事务内完成。公开推荐排除私有 Project、使用 Protocol 级权限的 Project、已删除的 Project/Protocol；讨论检索保留 Protocol 范围限制。检索本身不授予源资产访问权限。
- 模型调用不记录原始科研文本或供应商错误正文。记录供应商报告的 token 用量，未知价格保持未知而不是记作免费；取消的调用仍保持取消。

上述降级覆盖 Protocol/讨论的向量索引。Knowledge、Record 及其他确定性检索入口保留已有实现，本次调整不为它们增加 AI 依赖。

## 部署与迁移

安装锁定的正式依赖，并在启动新版 API 前执行正常数据库迁移。`0058_optional_embeddings` 仅允许向量字段为空，不删除文本，也不重写已有向量。

外部模式（`MASTERBRAIN_CALL_MODE=external`）需要支持 `POST /api/endpoints/embeddings` 的兼容 Masterbrain 服务（0.12.0 提供），并配置私有传输与访问控制、对应的 Qwen 供应商和独立的用量接收端。旧服务缺少该接口时降级为关键词检索，Platform 不会绕过它直接请求供应商。外部模式不代表共享数据库，也不会自动切换供应商。

重新开启 AI 不会自动批量补算向量。已有关键词分段仍可检索，后续受支持的资源索引操作可以生成向量。需要完整语义覆盖的部署，应另行安排范围明确、可计量的索引重建；不能仅重启 API 就认定补算完成，也不能直接改变模型或维度。

只要存在关键词分段，降级迁移就会拒绝恢复 `NOT NULL`。应恢复经过验证的升级前备份，或先明确执行并验证兼容的索引重建；不能为满足旧结构而删除行或伪造向量。回滚须遵循正常备份恢复流程。

## 验证

离线 API 回归覆盖正式包接口、分批、关闭 AI、传输故障、取消、无效向量、模型与维度契约及用量归属。隔离 PostgreSQL 回归覆盖迁移升降级、并发原子替换、含标点的关键词、AI 恢复，以及公开/私有/已删除范围隔离。测试使用合成模型响应，不代表真实供应商质量或可用性验收。
