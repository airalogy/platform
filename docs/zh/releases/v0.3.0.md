# Airalogy Platform v0.3.0

本版本改进 Protocol 编写、可移植下载与 Records 引导导入。产品及包含的 API、Web、Instrument Interface、Gateway、Compute Runner 版本统一为 0.3.0。

## 主要变化

- 下载当前准确 Protocol 的 CSV 模板，查看字段要求，先校验而不创建 Record，再明确确认导入。确认时重新检查数据、权限及预检是否过期。
- CSV/TSV 表头须匹配 Protocol 字段标识；未知或重复列、表格错误值及不符合定义的数据会得到按字段分组的中英文提示。支持 UTF-8 BOM，不猜测别名、不修补科研数值、不静默丢弃失败行。
- Record 表单通过已发布 AIMD 运行时执行客户端 Assigner，保留自动、手动及首次自动计算。校验混合客户端/服务端依赖图，上游失败时停止下游，计算未完成或失败时阻止提交。
- 通过正式发布的 Masterbrain 0.13.0，在 AI 辅助 Protocol 生成及编辑中优先以客户端 Assigner 实现适合的简单计算。外部服务、特权操作及重型计算仍使用服务端 Python；AI 产物仍是可编辑草稿。
- 按权限下载准确存储版本的标准 `.aira` 归档或 ZIP 源文件包，排除数据库 Records、环境密钥及执行缓存，保留原有 ZIP 集成兼容性。

## 升级与恢复

相对 v0.2.0 没有新增数据库迁移，目标版本仍为 `0075_legacy_file_metadata`。升级前核对实际数据库版本，不根据应用版本推断。更早部署须遵循 [v0.2.0 迁移说明](./v0.2.0.md)。

API 与 Web 应配套升级，并使用准确发布清单及不可变执行器镜像。API 与隔离执行器须使用同一 Airalogy 版本；执行器还会挂载配套 API 版本中的共享 Assigner 校验模块，不应混用旧宿主与新的挂载执行代码。现有外部 PostgreSQL 和对象存储保持不变。

API 已锁定 Masterbrain 0.13.0；如果单独部署 Masterbrain 服务，须先使其支持客户端优先请求契约，再启用该路径。升级 Platform 不会自动升级独立服务。

切换前验证恢复点，保留旧应用、配置和 Web 资源。使用隔离数据进行验收，不向演练服务提供生产 AI、通知或仪器凭据。提前说明暂停写入的影响；切换后核对版本身份，并以合成测试资产验证 Protocol 保存、Record 提交、模板预检确认和两种格式下载，再宣布验收完成。

从 v0.3.0 回退到 v0.2.0 无须降级数据库结构，但旧客户端不支持本次新增的客户端计算。回退前暂停写入，检查新建 Protocol 和 Record，保留其源文件与数值。不可盲目恢复旧数据库而丢失切换后的写入。详见[发布与部署规范](../release-and-deployment-identity.md)。

## 边界

客户端计算仅在交互式 Record 表单中执行，CSV/API 导入须提供必需的派生值。CSV 模板不替代 Protocol 校验和专业复核。本版本不引入任意旧表映射，不自动纠正临床数据，也不验证科学结论。真实模型质量及真实仪器仍须单独验收。
