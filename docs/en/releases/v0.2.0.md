# Airalogy Platform v0.2.0

This release adds reproducible analysis and governed Workflow composition. The product and included API, Web, Instrument Interface, Gateway and Compute Runner versions move together to 0.2.0.

## Main changes

- Protocol cards support explicit connections, pinned versions, conditions, approvals and declared scalar/file inputs, without requiring AI.
- Record and Project analysis retain exact source revisions, distinguish evidence synthesis from explicit typed joins, save reusable methods and compare immutable runs.
- Reviewed methods can be published to Workflow; supported built-in methods can become ordinary editable Protocol drafts with separate review and versioned publication.
- Selected built-in results can be published as Evidence and reviewed Knowledge without automatically sharing private reports or source files.
- AI assistance uses explicit consent and editable drafts. Embeddings use Masterbrain with keyword fallback. Local/hosted Node tooling and verification gates are aligned.
- Docker Protocol execution reports missing images and startup failures clearly, does not implicitly pull images, and no longer prints private runner parameters to API logs.

## Upgrade and recovery

The target database revision is `0075_legacy_file_metadata`. Do not assume a historical source deployment has the same baseline as the v0.1.0 release. Back up its database, object storage, configuration, source identity and web assets; restore to an isolated environment and test migrations before stopping production writes and taking the final backup.

Early databases with existing files but no storage metadata require an explicit, verified backend: `alembic -x legacy_storage_backend=oss upgrade head` (use `minio` only if that is where the original files reside). Missing legacy Workflow prerequisites are repaired before research-task creation. The file migration adds metadata without copying objects or changing existing object keys; it does not infer location from default configuration. Its downgrade retains additive fields to avoid destroying file locations.

Use a `pg_dump` version compatible with the source PostgreSQL major. An external PostgreSQL 17 database must not be replaced by an older bundled database as an incidental application upgrade. Keep existing external storage and database endpoints unless a separate migration has been approved. Do not supply production AI, notification or equipment credentials to rehearsal services.

Recover a failed cutover using the previous application and verified backup. Restore-based rollback may discard writes after the backup; do not reopen writes until acceptance checks pass. Read the [deployment identity documentation](../release-and-deployment-identity.md) and verify the exact published release manifest and image digests. A source tag alone does not certify deployment acceptance.

## Boundaries

Cross-Protocol Aira questions, versioned unit conversion/cleaning and repeat handling remain future work. Arbitrary Compute method promotion to ordinary Protocol and arbitrary Compute result publication are not included. Python is the primary compute path; existing optional R compatibility does not require installing R. Real instruments still require separate on-site qualification. Successful execution and organizational review do not validate scientific conclusions or establish autonomous research capability.
