# Airalogy Platform v0.4.0

While filling a Record, ask Aira what a Protocol field means and follow up with values for the fields just discussed. Review overwrites before applying them. Synthetic examples have a separate preview. The ordinary Record form handles submission and validation. This release uses Masterbrain 0.14.0.

A Lab can opt into external Agent access. Users issue expiring, revocable tokens for a specific Project to read permitted data or preview CSV imports and Record revisions over HTTP or MCP. Each write requires confirmation in Platform by the token owner. Access is disabled by default. See the [external Agent guide](../external-agent-access.md).

This release also ships scenario kits for sample registration and numerical results, fixes Record resource references, and checks for network conflicts before deployment.

## Upgrading from v0.3.1

The database advances through 0076 (scenario kits), 0077 (Record resource reservation links) and 0078 (external access policies, tokens, approvals and audit). Rehearse migration and recovery on an isolated copy, verify a recovery point before cutover, retain previous artifacts and configuration, and run network preflight against the installed subnet. Rollback planning must account for writes and audit history since cutover and verify the previous application's compatibility with the migrated schema. See the [release and deployment policy](../release-and-deployment-identity.md).

After upgrade, use a dedicated test Project to check a conversational form edit and a synthetic preview, followed by scoped token reads, a browser-approved write and access denial after revocation.
