# Airalogy Platform v0.3.1

This compatible patch fixes application footer visibility. Included component versions are aligned to 0.3.1; no scientific-data or permission behavior changes.

## Fix

Company and configured compliance information now remain visible on the home page and ordinary application pages, even when an older Record page saved a hidden-footer preference in browser storage. Users do not need to clear local data.

Record entry and report pages still hide their own footer through route metadata, without mutating global theme state. Coverage includes stale storage, narrow and desktop layouts, anonymous access, and navigation back from a Record report.

## Upgrade and recovery

From v0.3.0, this patch has no new database migrations, dependency upgrades, or storage-engine changes. The database revision remains `0075_legacy_file_metadata`; external PostgreSQL and object storage remain unchanged.

Deploy the verified release set, preserve the installation's company and compliance configuration, and retain its previous application and web assets. Verify footer visibility after a reload and navigation; do not discard browser data as a workaround. Application rollback to v0.3.0 requires no schema downgrade or database restore, so post-cutover writes must be preserved. Older deployments still require their actual source-to-target migration and recovery checks under the [release policy](../release-and-deployment-identity.md).
