# Airalogy Platform v0.4.1

Hosts that execute Protocols with Docker can set `AIRALOGY_PROTOCOL_EXECUTOR_NETWORK` on the API to the name of an existing dedicated bridge. Run the deployment network preflight before creating the bridge and again before cutover. The bridge must have one private IPv4 subnet and a usable gateway. The executor resolves the gateway for host callbacks and pins the inspected network ID on each run. If the configured network disappears, the run fails and the user can retain their draft.

Leaving the setting empty preserves the previous Docker network selection. The patch adds no database migration. Installations upgrading directly from v0.3.1 must also complete the database and recovery steps in the [v0.4.0 release notes](./v0.4.0.md). After installing the patch, test a Protocol from the API and verify access to the host endpoint from the selected bridge.
