# Airalogy Platform v0.1.0

The first formal Airalogy Platform Community Edition release brings together research collaboration, structured experimental records, organizational knowledge and governed research automation.

## Included in this release

- **Research workbench:** state-oriented entry points, recent-work continuation, shared layouts and typography, bilingual terminology and narrow-screen interactions.
- **Core research assets:** Labs, Projects, membership and permissions, Protocols, Workflows and Records; protocol creation/reuse/import, validated record submission/revision, search and export. Record tables offer all/default column controls with saved preferences; export dialogs retain screen gutters.
- **Knowledge and logs:** personal, Project and Lab Knowledge, private paper libraries and Research Logs with access control, provenance, review and asset links.
- **Research Tasks and Aira:** planning and execution under explicit scope, approvals and resource constraints, with human collaboration, compute execution, data assets and durable results. AI remains optional; deterministic core operations work without AI.
- **Instrument integration infrastructure:** Gateway pairing, source/package review, separate installation, qualification records, activation grants, version-pinned jobs and raw-file delivery. Local onboarding, bounded software observation, fixed HTTP/file interfaces and browser/macOS interface references are included.
- **Private deployment:** single-Lab initialization, account permissions, same-origin `/docs/`, version/digest verification, backup/restore, upgrade/rollback and sanitized support bundles.
- **Published dependencies:** AIMD Core 2.16.0, Editor 1.12.0 and Renderer 2.13.0 are consumed directly, without a temporary Renderer patch.

## Installation and verification

Download `airalogy-platform-deploy-v0.1.0.tar.gz` from this Release and verify its accompanying `.sha256` file. Follow `docs/en/single-lab-deployment.md` and `docs/en/release-and-deployment-identity.md` inside the archive. From `deploy/single-lab`, run `./platformctl preflight`, `./platformctl install` and `./platformctl status` after configuring the installation.

The release manifest binds immutable API, Web, Protocol Executor and PostgreSQL image digests and the database migration revision. Images support `linux/amd64` and `linux/arm64`. Version-matched Compute Runner and Instrument Gateway wheels/source distributions are separate Release assets. Verify Gateway provenance before installation; a successful installation is not equipment qualification.

The release workflow checks component versions, lockfiles, tests, builds and provenance. Before publishing attachments it exercises fresh installation, account permissions, backup/restore and same-release upgrade/rollback using the exact image set. Separate verification workflows cover full browser, research integration and isolated instrument tests.

## Qualification boundaries and upgrade notes

- **No real-instrument pilot has been qualified.** Validation uses software, simulators and synthetic equipment data. This does not establish automatic onboarding or safe remote control of arbitrary vendor instruments. Equipment identity, operation scope, interlocks, stop behavior and data accuracy require independent on-site qualification and authorization.
- Gateway local tools target POSIX environments; native interface references target macOS. Browser simulation actions, native read-only observation and hardware control have separate authority boundaries. General-purpose Windows instrument automation is not promised.
- AI-generated source, protocols and suggestions remain subject to preview, review and execution gates. This release does not promise unsupervised end-to-end autonomous research.
- This is the first formal release, so no earlier formal release exists for cross-version upgrade certification. Same-release recovery rehearsals do not establish compatibility with every historical development database. Back up existing trial/development instances and validate migrations and recovery on an isolated copy before switching.
- Rollback can restore data to a backup point and discard later changes. Back up first and confirm the impact. Backups contain sensitive configuration and require restricted access and separately stored encryption-protected copies.
- The single-Lab deployment is not an HA or regulatory certification offering. Keep real data, secrets and customer operational records out of the public repository.
